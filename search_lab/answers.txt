* State S: The current grid coordinates of the robot (x, y)[cite: 18].
* Actions A: Up, Down, Left, Right[cite: 17, 18].
* Transition T: Updating the coordinates by 1 unit in the direction of the action to a free cell[cite: 17, 18].
* Initial state s0: The coordinates where the symbol 'S' is located[cite: 18].
* Goal G: The coordinates where the symbol 'G' is located[cite: 18].
* Cost c: 1 for every movement[cite: 17, 18].

(a) The information necessary to specify a state is the agent's current position as a coordinate pair (x, y)[cite: 18].
(b) An action is invalid if it moves the robot into an obstacle ('#') or off the map boundaries[cite: 18].
(c) Yes, this is a deterministic search problem because every action has exactly one predictable outcome[cite: 18].
(d) A solution would constitute a valid sequence of actions (a path) that transitions the robot from S to G without crossing obstacles[cite: 18, 19].

Task 4: Inspect the A* Algorithm
* State: Represented as a `(r, c)` tuple in the `search` function[cite: 22].
* Action: Represented by the directional offsets `[(0,1), (0,-1), (1,0), (-1,0)]`[cite: 22].
* Transition: Adding the action offset to the current state to generate a neighbor[cite: 22].
* Goal test: Checking `if current_state == goal_state`[cite: 22].
* g(n): The variable tracking the number of steps taken from the start[cite: 20, 22].
* h(n): The `manhattan_distance` function call[cite: 20, 22].
* f(n): Implicitly calculated as `g + h` and pushed to the priority queue[cite: 20, 22].
* Frontier: The `heapq` (priority queue) named `frontier`[cite: 20, 22].
* Visited states: A `set` named `explored` or `visited` tracking `(r, c)` tuples[cite: 20, 22].
* Path reconstruction: Handled by maintaining the path array inside the queue elements[cite: 20, 22].
(a) The data structure used is a priority queue (min-heap)[cite: 20, 22].
(b) The program selects the next state by popping the node with the lowest `f(n)` value from the heap[cite: 20, 22].
(c) The heuristic is calculated for each valid neighbor before pushing it to the frontier[cite: 20, 22].
(d) Yes, it computes `f = g + h` to use as the sorting key in the priority queue[cite: 20, 22].
(e) It adds expanded states to a `visited` set and checks neighbors against this set before appending to the frontier[cite: 20, 22].

Task 6: Investigate the Heuristic
Explanation: Manhattan distance is appropriate because the robot is constrained to a grid and can only move horizontally and vertically (no diagonals), exactly matching the Manhattan distance metric[cite: 20, 23].
1. If h(n) = 0: The search degrades into uniform-cost search (equivalent to BFS here), expanding states radially and vastly increasing the expanded states count[cite: 23].
2. If h(n) = Euclidean distance: The heuristic is admissible but strictly smaller than Manhattan distance. The agent finds the optimal path but expands more states than Manhattan because the heuristic is less "informed" (underestimates the true cost more)[cite: 23].
3. If h(n) * 2: The heuristic becomes non-admissible (overestimates the cost)[cite: 23, 24]. The search becomes greedy, expanding extremely few states but risking a suboptimal (longer) path[cite: 24].

6 Final Reflection
1. Formulating the problem separates understanding from implementation, ensuring that states, transition rules, and goal conditions are mathematically clear before coding begins[cite: 19, 25].
2. A* is "informed" because it uses problem-specific knowledge (the heuristic) to estimate the distance to the goal, steering the search direction instead of blindly exploring all paths[cite: 16, 25].
3. The heuristic dictates performance: an optimal, admissible heuristic minimizes expanded states, while a poor one degrades to blind search, and an overestimating one loses optimality[cite: 23, 24, 25].
4. The LLM provided the Python boilerplate, data structure choices (like `heapq`), and syntax scaffolding[cite: 20, 25].
5. An untested LLM implementation could result in infinite loops, suboptimal pathing disguised as success, or crashes on edge cases, underscoring that AI engineering requires rigorous human validation[cite: 21, 24, 25].
